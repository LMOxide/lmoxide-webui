# LMOxide web UI

The web front end for an [LMOxide](../lmoxide) server: public server status and who's online,
account registration, a player's own account page, and the moderator/admin console (players,
accounts, bans, broadcasts, maintenance mode, API keys, audit log).

It talks only to `lmoxide-api` over HTTP. The contract is `../lmoxide/docs/openapi.json`; see
`../lmoxide/docs/WEB-UI.md` for the authentication flow and what each scope may see.

Stack: Vite, React 19, TypeScript, Tailwind CSS 4, shadcn/ui (Radix), TanStack Query,
React Router, `openapi-fetch` with types generated by `openapi-typescript`.

## Developing

```sh
# in ../lmoxide: an API on 127.0.0.1:8090 with demo accounts
tools/web-dev-backend.sh

# here
pnpm install
pnpm dev                     # http://localhost:5173
```

The dev server proxies `/api/*` to `http://127.0.0.1:8090` (strip `/api`), the same layout as
production behind a reverse proxy, so CORS doesn't come into it. Point it elsewhere with
`LMOXIDE_API=http://host:port pnpm dev`.

Demo logins (from the backend script): `admin`, `moderator`, `player`, `banned`, each with
password `<name>-password`.

| Script | |
|---|---|
| `pnpm gen:api` | regenerate `src/api/schema.d.ts` from `../lmoxide/docs/openapi.json` after an API change |
| `pnpm typecheck` / `pnpm lint` | `tsc -b` / oxlint |
| `pnpm build` | static files in `dist/` |

## Layout

- `src/api/client.ts`: the typed client, `ApiError`, bearer token, `unwrap()`
- `src/lib/auth.tsx`, `auth-context.ts`: login session (kept in `sessionStorage`, no cookies),
  scope checks; a 401 `unauthorized` anywhere logs out
- `src/pages/`: one file per route; `src/components/`: shared pieces (moderation dialogs,
  tables); `src/components/ui/`: shadcn components
- `src/lib/rules.ts`: username/password rules mirrored from the server for form hints

## Deploying

`pnpm build`, then serve `dist/` as a single-page app (unknown paths → `index.html`). By
default the UI calls the API at `/api` on its own origin, so put both behind one reverse
proxy (UI at `/`, `/api/` → `api:8090`) and set `LMOXIDE_API_TRUST_FORWARDED_FOR=true` on the
API. To call an API on another origin instead, build with `VITE_API_URL=https://api.example.org`
and allow the UI's origin with `LMOXIDE_API_CORS_ORIGINS`. To serve under a sub-path, build with
`--base /admin/`.
